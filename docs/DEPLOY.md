# Размещение NeoPos

Временная схема: **сервер и база — Render**, **панель и касса — Vercel**, код — GitHub
`Sariofficial23/Neopos`. Позже сервер переезжает на платный хостинг без изменения кода.

## 1. Сервер на Render

В репозитории лежит файл `render.yaml` — по нему Render сам создаёт сервер и базу.

1. Зайдите на https://render.com и войдите через GitHub (аккаунт `Sariofficial23`).
2. Нажмите **New +** → **Blueprint**.
3. Если Render попросит доступ к репозиториям — нажмите **Configure account** и разрешите
   доступ к репозиторию `Neopos`.
4. Выберите репозиторий **Neopos** и нажмите **Connect**.
5. Render покажет, что будет создано: сервер `neopos-api` и база `neopos-db`. Нажмите **Apply**.
6. Подождите 3–5 минут, пока статус сервера станет **Live**.
7. Откройте сервис `neopos-api` и скопируйте его адрес вверху страницы —
   он выглядит как `https://neopos-api.onrender.com` (может быть с добавкой, например
   `neopos-api-x1y2.onrender.com`).
8. Проверьте: откройте в браузере `адрес/api/health` — должно показать `{"ok":true}`.

Этот адрес нужен для шага 2.

### Ограничения бесплатного Render

- Сервер **засыпает** после 15 минут без запросов; первое обращение после сна занимает
  около минуты. Для демонстрации подходит, для работы заведения — нет.
- Бесплатная база **удаляется через 30 дней** после создания. До этого срока нужно
  перейти на платную базу (или платный сервер) — иначе данные пропадут.

Сервер сейчас: **https://neopos-api-bvue.onrender.com** (создан 21.11.2026, бесплатная база истекает около 21.12.2026).

## 2. Панель и касса на Vercel

Проекты уже созданы и привязаны к репозиторию — каждый `git push` в ветку `main`
обновляет их автоматически:

| Проект | Папка | Адрес |
|---|---|---|
| `neopos-panel` | `panel/` | https://neopos-panel.vercel.app |
| `neopos-terminal` | `terminal/` | https://neopos-terminal.vercel.app  |

Важно: на бесплатном тарифе Vercel сборки, запущенные обычным `git push`, блокируются
(автор коммита не привязан к аккаунту Vercel). Пока так — сборку запускает Claude через
подключение к Vercel, либо вручную кнопкой **Redeploy** в проекте.

Обоим нужно указать адрес сервера из шага 1.7 — переменная **`VITE_API_URL`**
(без `/api` на конце), после чего пересобрать проект. Это может сделать Claude,
если прислать ему адрес сервера.

Вручную: Vercel → проект → **Settings → Environment Variables** → добавить
`VITE_API_URL` = адрес сервера → **Deployments → … → Redeploy**.

## 3. Первый вход

1. Откройте панель, нажмите «Регистрация», создайте своё заведение.
2. В разделе «Сотрудники» задайте ПИН-коды.
3. Откройте кассу, один раз введите логин и пароль от панели (привязка устройства),
   дальше вход по ПИН-коду.

Когда заведение создано, свободную регистрацию можно закрыть: в Render у сервиса
`neopos-api` → **Environment** → добавить `ALLOW_REGISTER` = `false`.

## 4. Переезд на платный сервер

Нужны только три вещи: Node.js 22+, PostgreSQL и переменные окружения
`DATABASE_URL`, `JWT_SECRET`, `NODE_ENV=production`. Запуск: `npm install`, затем
`npm run start -w server`. Таблицы создаются сами при первом запуске.

## 5. Касса для Windows

Приложение лежит в папке `desktop/` и открывает кассу https://neopos-terminal.vercel.app,
поэтому изменения кассы попадают в приложение без переустановки.

**Выпуск новой версии установщика:** отправить тег вида `vX.Y.Z`:

```
git tag v0.2.0
git push origin v0.2.0
```

GitHub соберёт `NeoPos-Setup.exe` на своих серверах (вкладка **Actions**, около 5–10 минут) и
опубликует его в **Releases**. Установленные приложения сами скачают новую версию и поставят её
при следующем закрытии.

Ссылка для скачивания (на неё ведут кнопки в панели и кассе):
https://github.com/Sariofficial23/Neopos/releases/latest/download/NeoPos-Setup.exe

Установщик без цифровой подписи: при первом запуске Windows покажет «Windows защитил ваш
компьютер» → «Подробнее» → «Выполнить в любом случае».

Локальная сборка: `cd desktop`, `npm install`, `node node_modules/electron/install.js`,
`npm run dist` → `desktop/dist/NeoPos-Setup.exe`. Проверка без установки: `npm run smoke`.
